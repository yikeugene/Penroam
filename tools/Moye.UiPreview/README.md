# Penroam offscreen WPF layout preview

Run from the repository root on Windows:

```powershell
./scripts/preview-ui.ps1
```

This tool uses the existing .NET SDK and package cache in `.tools` to build a separate STA console renderer. It creates the real `MainWindow`, detaches its `Content`, and renders it with the application's `App.xaml` resources, an in-memory notebook fixture, and `PageEditor` through `Measure`, `Arrange`, and `RenderTargetBitmap`.

The tool does not call `Window.Show` or `Application.Run`, send input, capture the desktop, use a UI Automation client, or read or write a user database. It checks that the content has no `PresentationSource` and the main window's native handle remains zero. All notebook pages, sections and note contents are synthetic test data.

Startup is initialized through the real view model and must leave the library visible without opening a notebook. The renderer captures a four-notebook library with several categories and a long title, a first-run empty library, and a search with no results, then explicitly opens the fixture through `OpenAsync` to capture the editor at Fit Page and Fit Width. A library that exceeds the available height is also captured after scrolling to its last notebook. Separate detached previews show the reusable paper picker with Ruled selected and the real New Notebook dialog content. The dialog is constructed without an owner and never shown.

These images support internal layout review; they do not validate live UI interaction. Touch, pen input, Windows scaling, the system title bar, popup menus, and keyboard focus require separate verification. Images are rendered at 96 DPI, and their dimensions describe the content area without operating-system window borders. Button checks use declared `Visibility` and ancestor visibility because `IsVisible` does not describe layout in an offscreen tree without a presentation source.

Each scene must contain its expected controls. Home requires New Notebook, Import Folder, Workspace, Backup & recovery, Restore backup, Check for updates and All tools, plus Notebook actions on populated cards. The editor requires every writing tool, labelled Pen settings, Undo/Redo, fit/zoom/focus controls, Section actions, Page actions, Manage pages, Two pages, Reference, Export and All tools. All nine category menu targets must remain visible, labelled and pointer-reachable at both 1400 × 960 and 1024 × 700 DIP. Focus requires its writing tools, All tools, Add Page, Undo/Redo and Exit Focus; guard scenes check both docking sides, settings-popup placement and an actual read-only ReferencePane. The full-height writing viewport and reference content must stay clear of the floating tools. Section navigation must retain at least 100 DIP for thumbnails.

The paper picker requires seven radio choices with exactly one selected; the eraser popup requires both eraser mode buttons; the scrollable pen popup requires its color controls at the top and Draw and Hold/advanced Manage pens at the bottom. Required actions must be visible without horizontal scrolling. Touch-target checks include template radio cards, checkboxes, buttons, comboboxes and category menu items, excluding native scrollbar parts. The process exits unsuccessfully when required controls are missing or measured targets are too small, overlapping, or outside the rendered area.

Library checks distinguish the first-run Create a Notebook action from the no-results Clear Search action, verify the current count and explanation are displayed, and require the visible create/search/recovery controls to be keyboard tab stops with readable labels and 44 DIP targets. Both clear-search buttons are invoked through their real routed click handlers; all four notebook summaries must return. Title and category matching are checked without case sensitivity. These detached checks verify command behavior and declared keyboard accessibility, not actual native focus or key routing.

Each Notebook actions menu is assigned its real placement target without opening it; the menu and all four Open/Pin/Cover/Delete entries must receive the matching notebook summary. Neither action is invoked. The four cover backgrounds must resolve to four distinct colors through the actual item templates. Searching an empty library must still offer Clear Search; clearing it must restore the first-run create action without adding a notebook.

The import scene also hit-tests the rendered center of Cancel Import and checks that the enabled button is above any blocking overlay. This is a detached visual-tree check; it does not start or cancel an actual document conversion.

Settings previews detach the real `Popup.Child` while `IsOpen` remains false, inherit the main-window typography, and use the content's natural height within its scroll limits. Pen settings have top/bottom scenes so Draw and Hold and advanced Manage pens remain reachable. They render content without creating a native popup or invoking click/keyboard handlers. The Pixel Eraser highlight represents the application's initial remembered mode because the main window's Loaded handler is intentionally not dispatched.

Typing previews call the real window commands against a registered synthetic page editor. They verify that Type resumes text without duplicates, formatting updates the model, new boxes copy style without note content, and overflow raises a warning. Opening Text formatting with no selection must explain the missing context without creating a text item; Pens closes it without editing content. Text color retains an explicit label, and Continue text stays visible but disabled until the selected text overflows. The font, size and alignment pickers must also be at least 44 DIP. These command checks do not exercise native focus, input-method composition or keyboard routing.

Fit Width validation measures every realized page host and editor in the selected spread in viewport coordinates: their horizontal edges must align, the combined paper bounds must leave outer gutters between 0 and 60 DIP, and the spread must cover at least 85% of the viewport width. Two-page rows additionally require a fixed 24-DIP inner gutter and top-aligned pages. Fit calculations use the same geometry helper as the application; rendered bounds remain the assertions. The dialog preview checks its real template choices and Create Notebook action using the same button layout rules. Home scenes require Import Folder in populated, empty and search states; folder-summary scenes require explicit acceptance when some files failed. These checks do not open a folder picker, perform Explorer drag/drop or run Office conversion.

All tools previews obtain `MainWindow.CreateFeatureCommands()` from the same synthetic shell, with `_ready` temporarily set to represent an initialized library and an actual synthetic editor registered for the editor context. They snapshot names, IDs, parent relationships, locations, shortcuts, keywords, checked state and availability, then replace every executable callback and dynamic getter. They never invoke production import, export, deletion, backup or update actions. No handcrafted five-command substitute is used. Every parent, child and help topic must remain in the list; each row's title and a 44-DIP target must be reachable through vertical scrolling at both dialog sizes. Longer explanations wrap in their own scroll area. Category browsing, multiword search, no matches, Reset, instruction-only help and disabled-context explanations use the real dialog controls without depending on its private row class. This does not verify native keyboard routing, IME, popup opening, focus restoration or command dispatch after a modal window closes.

For separate live desktop checks, run the built preview executable with the repository root followed by `--interactive`; append `--compact` to start at the application's 1024 × 700 minimum window size. This opens the real application shell with a disposable in-memory notebook repository; it does not access SQLite or the user's notebook library, and its update service is disabled. Writing and workspace preferences stay under `artifacts/interactive-preview/`. Use only synthetic input/output files and do not restore or overwrite real notebooks during verification. Check the nine category menus, All tools category/search/reset/disabled states, Tab/Shift+Tab and visible focus, text formatting/color, direct layout/reference/page-management actions, advanced pen settings, and focus mode with guards/reference on both docking sides. These are live checks to perform, not claims established by detached screenshots. Close the synthetic window before rebuilding the preview.

Additional detached scenes cover free typing/Meeting paper, study questions/resume/regions, PDF layout, and appearance/practice/history. Reports are `free-typing-preview.json`, `study-preview-report.json`, `pdf-pagination-preview.json` and `insight-preview-report.json`. The appearance scene computes real visual-search matches but supplies read-only result rows to the detached list because a detached Window cannot enter its native Loaded lifecycle. It does not claim live asynchronous search or desktop interaction coverage.
The in-app updater adds seven notification states at both supported sizes: available, downloading, ready, preparing, error, current and checking. Files are `ui-preview-update-{state}-{1024,1400}.png` and `update-preview-report.json`. These verify button bounds, scrolling release notes, action routing and accessibility declarations. `update-integration-report.json` records five additional checks against the real MainWindow with fake update services: startup offers, offline/manual errors, dismissal, payload invalidation and shared in-flight checks. They do not open native windows, contact GitHub or execute an installer. Actual Setup replacement/relaunch still requires a disposable Windows installation acceptance run.
